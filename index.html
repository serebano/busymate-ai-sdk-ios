Busymate AI SDK for iOS

Busymate AI hosted chat inside your iOS app: a WKWebView host with the frozen identity bridge and a tap-triggered microphone adapter.

What it does

An independent Swift package for iOS. BusymateBridge answers the hosted chat's identity requests from your app (identity wire v2, immutable build 2.0.0); BusymateMicrophone asks iOS for microphone access only when the user taps the chat's microphone or voice control (adapter 1.0.0). Existing v1 integrations can keep BusymateAIWebViewBridge; do not install both identity handlers on one chat.

Hosted chat in WKWebView

Load your workspace's chat URL with channel=ios. Hosted chat updates ship independently of your App Store release.

Identity bridge v2

Your app supplies the current account and mints fresh assertions from your own backend; renderer termination and foreground resume are handled.

Microphone on tap

No OS prompt merely on opening chat. Only an OS grant plus an allowed-origin WebKit media grant permits recording.

Example app

The example app (BusymateSDKExample) consumes this SDK as a local Swift package, with Chat, Settings and Events tabs.

Install

Install with Swift Package Manager and pin the exact version.

  1. In Xcode choose File → Add Package Dependencies and enter the repository URL. Select Exact Version 1.0.2 and add the BusymateAI product to your app target.

    https://github.com/serebano/busymate-ai-sdk-ios.git

  2. Or declare it in a package manifest.

    .package(url: "https://github.com/serebano/busymate-ai-sdk-ios.git", exact: "1.0.2")
// In your target's dependencies:
.product(name: "BusymateAI", package: "busymate-ai-sdk-ios")

  3. import BusymateAI, install BusymateBridge and BusymateMicrophone before loading your tenant's HTTPS chat URL, forward WebKit's media permission, and add a localized NSMicrophoneUsageDescription to your Info.plist.

Identity linking and the microphone

Both bridges are installed by your app before the chat's first load. Your native app release is what installs or upgrades native SDK code; the hosted chat updates independently.

Identity linking

BusymateBridge (wire v2, build 2.0.0) asks your app for the current account and for a fresh single-use assertion minted by your authenticated backend. External HTTPS opens stay OS-owned, with an optional ASWebAuthenticationSession callback scheme. Read identity.md.

Microphone

BusymateMicrophone (wire 1, adapter 1.0.0) requests iOS microphone permission only on the user's tap; denial offers Retry, revoked permission is rechecked, and a cancelled chat cannot start capture after a late reply. Read microphone.md. Download the adapter: latest release · pinned 1.0.2 · SHA256SUMS.
